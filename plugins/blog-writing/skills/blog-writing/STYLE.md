# 문장·구조·표기 원칙

섹션을 쓰거나 고칠 때 항상 적용한다.

## AI 티 패턴 회피

극적 전환문("이제는 다릅니다"), 완벽 대칭 병렬 구조, "단순히 X가 아니라 Y", 과도한 볼드, 문서 메타 언급("앞서 예고한"), 혼잣말 톤 헤딩("~할까"→"~인가" 또는 평서형).

## 구조

- **들어가기는 헤딩 없이** 제목 아래 리드 문단으로, 마지막 섹션은 **"마치며"**. 도입을 질문으로 열었으면 마치며에서 그 질문에 답하는 수미상관 구성
- 헤딩 번호 depth 정책(2단계 vs 3단계)은 공동 저자와 초기에 합의하고 문서 전체 통일
- **섹션 번호 하드참조 금지** — "앞서 6.2에서" 대신 "앞서 VPC 모드로 배포한"처럼 내용 지칭 (번호 재배열에 안전). 아키텍처 흐름 번호 참조는 허용하되 라벨이 흐름 목록의 실제 항목과 일치하는지 검증
- **표 도입 문장은 표에 없는 정보만** (예: 필드명↔모드명 매핑). 표 내용을 미리 요약하는 문장 금지. 표 뒤에는 선택 가이드/종합 문단
- **허수아비 질문 금지** — 가상의 독자 질문을 만들 땐 실제 시행착오에서 나온 질문만. 애매하면 질문 형식을 버리고 방향 중심 서술로

## 코드 예시

- 코드 예시 스타일은 문서 전체에서 통일 (공동 저자가 bash CLI를 쓰면 내 섹션도 bash)
- 앞서 나온 명령에 파라미터를 추가하는 예시는 `...(앞선 배포 명령과 동일한 파라미터 생략)...` 형태로 중복 제거 — 단 `#` 주석 + `\` 연속은 bash 문법상 깨지므로 쓰지 않음

## 표기

- 컴포넌트는 풀네임 접두어(예: AgentCore Runtime)
- 슬래시 풀기 3규칙: 어느 쪽이든→이나, 둘 다→와, 나열→쉼표
- AWS 공식 한국어 용어 사용(예: 퍼블릭 인증서), 첫 등장 "한국어(English)" 병기 후 영문
- 예시 도메인은 RFC 2606 계열(`idp.internal.example.com`), 계정 ID·시크릿은 마스킹. 데모 실제 도메인과의 캡처 불일치는 캡션에서 처리
