# Blog Writing — AWS 테크 블로그 원고 작성

문장·구조·표기 원칙은 [STYLE.md](STYLE.md), 이미지·다이어그램 원칙은 [IMAGES.md](IMAGES.md)에 있다. 섹션을 쓰거나 고치는 모든 단계에서 STYLE.md를 적용하고, 이미지 언급이 나오는 순간 IMAGES.md를 참조한다.

## 1. 시작 전 확인

- **작업 폴더**: 사용자에게 확인한다. 정해진 폴더가 없으면 블로그별 폴더(`<YYYY-MM-xx>-<타이틀>/` 형태 권장)를 만들어 제안. 초안은 `draft-*.md`로 저장
- 확인할 것: 주제/소재, 게시 채널, 공동 저자와 섹션 분담(@담당자 표시된 개요가 있으면 그 구조를 따름), 참고 자료 위치(검증 노트, 데모 계정, 발표 자료)
- 데모 계정이 있으면 프로필을 설정해 두고 작성 중 실측 검증에 활용

**완료 기준**: 주제·게시 채널·공동 저자·참고 자료·작업 폴더 다섯 가지가 모두 답해짐. 하나라도 비면 작성을 시작하지 말고 사용자에게 묻는다.

## 2. 톤 분석

저자의 **기존 게시 블로그 2~3편을 WebFetch로 분석**해 문체 기준을 잡는다. 추출할 것:

- 도입 전개 방식 (예: 질문 기반 문제 제기, 성과 선언형)
- 볼드 밀도(단락당 2~3개 수준), 헤딩 스타일(서술형/질문형), 표 활용 패턴
- 시그니처 문장 (예: "~분들께 실질적인 참고가 되기를 바랍니다" — 위치는 마치며)

참고한 톤은 어디까지나 문체이며, 기존 글의 시리즈 링크를 함부로 걸지 말 것(참고용 ≠ 시리즈 연속).

**완료 기준**: 위 세 항목이 실제 글에서 추출되어 문체 기준으로 정리됨. 기존 게시 글이 없으면 사용자에게 지향하는 톤을 물어 대신한다.

## 3. 구성안 컨펌 → 섹션별 작성

- 섹션별 구성안(각 섹션의 논점 불릿)을 먼저 제시하고 컨펌 받은 뒤 작성
- **섹션 초안은 채팅에만 보여주지 말고 작업 md 파일에 바로 반영한 후 검토를 요청**한다 (사용자가 에디터에서 검토)
- 수정 요청은 문장 단위로 반복되므로, 한 번 지적받은 패턴(번역투, 하드참조 등)은 같은 문서의 다른 곳에도 선제 적용

**완료 기준**: 구성안의 모든 섹션이 작업 파일에 반영되고 각각 사용자 검토를 거침. 검토 안 된 섹션이 남아 있으면 다음 단계로 넘어가지 않는다.

## 4. 사실 검증 (이중)

**공식 문서 검증:**
- 기능명·출시 시점 → What's New (공식 발표 기능명이 기준. 예: "VPC egress")
- 동작·제약 → devguide (요건은 원문 인용 수준으로 확인)
- 용어 3층위를 구분해 서술: 발표 기능명 / 문서 페이지명 / API 파라미터명 — 본문 첫 등장 시 관계를 한 문장으로 이어줄 것 ("API 설정에서는 `privateEndpoint` 블록으로 구성합니다")

**실측 검증 (데모 계정이 있을 때):**
- read-only 조회로 본문의 설정·명칭·리소스가 실제 배포와 일치하는지 대조
- 함정: **구버전 AWS CLI는 신규 API 필드를 응답에서 누락 표시** — `SDK_UNKNOWN_MEMBER`가 단서. "필드가 안 보임" ≠ "설정이 없음"
- 실측에서 발견한 부정확(예: 두 리소스의 allowedClients가 서로 다른 클라이언트)은 본문에 반영

**완료 기준**: 본문에 등장하는 모든 기능명·출시 시점·동작 제약이 공식 문서와 대조됨. 데모 계정이 있으면 본문의 설정·명칭·리소스도 전부 실측과 대조됨 — 표본 몇 개가 아니라 전수.

## 5. 공동 저자 협업·마무리

- 상대 섹션의 지적은 코멘트 형식(원문 인용 + 수정안 + 한 줄 근거)으로 전달, 위치는 Cmd+F 검색어로 안내
- 협업 문서 도구로 원고를 옮긴 뒤에는 붙여넣기 오류 패턴을 전수 점검: 문장 중복, 수정 전 구버전 문장 잔존, 문단이 불릿 안에 병합, URL이 `<https://...>` 꺾쇠로 감싸짐(마크다운 자동링크 잔재 — 코드 블록이면 복사 시 오류 유발), 코드 블록 언어 라벨 누락, 옮기는 과정에서 생긴 새 오타
- 원고 완성 후: 게시 채널이 요구하는 포맷(예: WordPress HTML) 변환과 최종 품질 리뷰를 별도 패스로 진행

**완료 기준**: 공동 저자 피드백이 원고에 반영되고, 협업 도구로 옮긴 경우 붙여넣기 오류 여섯 패턴이 문서 전체에서 점검됨.
