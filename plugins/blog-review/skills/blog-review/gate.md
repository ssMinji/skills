# 블로그 셀프 게이트 (리뷰어 전달 전 자기검열)

원고를 사람 리뷰어에게 넘기기 전에 6개 기준으로 점수화하고, 통과 조건을 못 넘으면 작성자(또는 작성 세션)가 먼저 고친다. blog-writing 마지막 단계와 blog-review 시작 단계가 공유하는 문서다.

## 통과 조건

- 총점(6개 평균) 70 이상
- **모든 항목이 최저선 이상** (총점이 높아도 한 항목이 최저선 미달이면 반려)
- 자기검열 반복은 **최대 2회**. 2회 후에도 미달이면 `gate-report.md`에 미달 항목을 명시한 채 리뷰어에게 전달 (점수 올리려고 글을 밋밋하게 만드는 것보다 사람 판단이 낫다)

## 기준 6개

| # | 기준 | 측정 방식 | 최저선 |
|---|---|---|---|
| 1 | 정합성 | 자동 재계산 위주. 그림/표 번호가 등장 순서와 일치, 본문 수치 ↔ 표·그림·코드 수치 재계산 일치, 본문 심볼 ↔ 코드 심볼 일치, 링크 전부 200, 아키텍처 흐름 번호 참조 일치 | 80 |
| 2 | 구조 완결성 | 체크리스트 7개 각 ~14점: 도입(문제 제기), 솔루션 개요, 실전 단계, 결과 증거(캡처/수치), 리소스 정리, 비용 언급, 다음 단계·CTA | 70 |
| 3 | 표기 규범 | 서비스 정식명(Amazon/AWS 접두사 첫 등장), AWS 한국어 공식 용어, 용어 혼용 전수 검색(예: 컨텐츠/콘텐츠, 워크플로/워크플로우), 용어 3층위(기능명·문서명·API값) 구분, 섹션 번호 하드참조 없음 | 70 |
| 4 | 중복과 군더더기 | `scripts/redundancy_metrics.py` 실행 결과에 재진술 판단(1건당 -5)을 더해 사용. AI가 썼는지가 아니라 읽기에 방해되는지만 본다 | 60 |
| 5 | 차별성과 근거 | WebSearch로 유사 블로그 3개 이상 확인 후 차별점이 본문에 한 문장으로 있는가(40), 실측 데이터·실패 경험이 있는가(40), 사용 모델·버전 등 재현 정보가 있는가(20) | 60 |
| 6 | 가독성 | 비문(주어-서술어 호응) 0건(40), 번역투 표현 3건 이하(30), 한 문단 5문장 이하(30) | 60 |

### 채점 원칙

- 1, 3, 4번은 스크립트와 전수 검색으로 재현 가능한 값만 쓴다. 감으로 매기지 않는다
- 2, 5, 6번은 판단이 들어가므로 **근거 문장을 인용**해서 점수를 적는다. 근거 없는 점수는 무효
- 감점 사유는 반드시 "원문 인용 → 수정안" 쌍으로 남긴다 (blog-review 코멘트 형식과 동일)

## 중복과 군더더기 지표 실행

```bash
python3 -I <이 스킬 폴더>/scripts/redundancy_metrics.py <원고.docx|.md>
```

측정 항목: 보일러플레이트 문단 반복, 문장 반복(동일 또는 한글 공통 구절 20자), 메타 강조 문장(핵심 등), 따옴표 조어 밀도, 6문장 이상 문단, 상투어 밀도. 출력 표를 `gate-report.md`에 그대로 붙인다.

스크립트가 못 잡는 것: 같은 뜻을 다른 문장으로 되풀이하는 **재진술**. 채점자가 섹션별 핵심 메시지를 한 줄씩 적어 겹치는 것을 세고, 1건당 -5를 스크립트 점수에서 뺀다.

측정하지 않는 것: 구호형 불릿, 섹션 구조 동형성, 문장 길이 분산, 과거형 비율. AI 티 탐지에는 쓰이지만 독자가 읽는 데는 방해되지 않는다. 가이드 글은 오히려 섹션 구조가 같아야 따라 하기 쉽다.

## gate-report.md 형식

작업 폴더 루트에 저장한다.

```markdown
# Gate Report: <블로그 제목>
회차: 1 / 2 | 판정: 통과 / 반려 / 2회 초과 전달

| 기준 | 점수 | 최저선 | 판정 |
|---|---|---|---|
| 정합성 | 85 | 80 | 통과 |
| ... |
| **총점** | 71 | 70 | **반려 (중복과 군더더기 미달)** |

## 감점 사유 (원문 인용 → 수정안)
### 중복과 군더더기 (55)
> (원문)
→ (수정안) — 이유
...

## 중복과 군더더기 지표 원본
(스크립트 출력 붙여넣기)
```

## 자기검열 루프

1. 채점 → `gate-report.md` 저장
2. 미달 항목의 감점 사유를 **그 항목만** 고친다 (통과한 항목은 건드리지 않는다. 다시 손대면 새 오류가 생긴다)
3. 재채점 → 회차 +1 로 리포트 갱신 (이전 회차 점수는 리포트 상단에 한 줄로 남긴다)
4. 통과하거나 2회를 넘기면 blog-review로 넘긴다

## 리뷰어 역할

게이트를 통과한 원고의 리뷰어는 오타, 정합성, 문체를 다시 보지 않는다. **기술적 정확성(서비스 동작이 실제와 맞는가)과 고객 관점(이 글을 받은 고객이 바로 쓸 수 있는가)** 두 가지에 집중한다. `gate-report.md`의 감점 사유 중 작성자가 "의도적으로 유지"라고 표시한 항목만 추가로 판단한다.
